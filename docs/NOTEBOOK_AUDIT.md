# 노트북 전수 검토

이 문서는 `notebooks/`의 네 파일을 보고서에서 어떻게 인용해야 하는지 정리한 감사 기록입니다. 노트북은 모델 선택 과정의 증거이고, 현재 운영 파이프라인은 `src/models/`입니다. 노트북 안에 남아 있는 삭제된 `src/routing/13_predict_all_link_speed.py` 등의 경로는 작성 당시 메모이므로 현재 실행 안내로 따라가면 안 됩니다.

## 1. `11_speed_model_baseline.ipynb`

### 목적

정적·시간·기상 피처로 어느 계열의 회귀모델이 기본 성능을 내는지 빠르게 비교한 초기 기준선 실험입니다. 선형모델, Random Forest/Extra Trees, Gradient Boosting, LightGBM/XGBoost 계열을 비교해 비선형 부스팅 모델을 이후 실험의 중심으로 고르는 역할을 했습니다.

### 핵심 결과

기록된 초기 XGBoost 기준은 대략 다음과 같습니다.

- R²: 0.6319
- MAE: 5.584 km/h
- RMSE: 7.436 km/h

### 해석

도로속도는 제한속도·도로등급·시간·기상·위상 특성이 비선형으로 상호작용하므로 단순 선형모델보다 트리 부스팅이 유리하다는 탐색 결과입니다.

### 보고서 사용법과 한계

- 사용: “초기 알고리즘 비교에서 XGBoost 계열을 선택했다”는 근거
- 사용 금지: 현재 공식 최종성능
- 이유: 초기 random split 성격이 강하고 현재 데이터 스키마·피처·계층 구조와 다릅니다. 동일 링크의 다른 시간이 학습과 평가에 섞이면 공간 일반화 성능이 낙관적으로 보일 수 있습니다.

## 2. `12_derived_features_lightgbm.ipynb`

### 목적

현재 B/C 모델의 핵심이 된 파생 피처를 단계별로 추가하면서 어떤 정보가 미관측 링크 속도 예측을 개선하는지 검증합니다. 파일명은 LightGBM이지만 후반 최종 비교에서는 XGBoost가 선택되었습니다.

### 데이터 상태 진단

- 행: 약 15,094,335
- 열: 약 93
- 고유 관측 링크: 44,960
- `sample_count_5min` 평균: 약 8.2
- 교통량/View-T 계열 결측: 약 60.7%
- 인구 계열 결측: 약 0.5%

따라서 외부 교통 피처는 강력할 수 있으나 전 링크 공통 정보가 아니며, XGBoost의 결측 처리에 의존합니다.

### 파생 피처 실험의 발전

노트북의 8~16차 실험은 다음 흐름으로 읽는 것이 좋습니다.

| 단계 | 핵심 변화 | 기록 R² | 의미 |
| --- | --- | ---: | --- |
| 8차 | 이웃속도 유무에 따라 B/C 분리 | 약 0.709 | 없는 피처를 한 모델에 억지로 넣는 것보다 계층 분리가 유리 |
| 9차 | 시간·도로·외부 피처 확장 | 약 0.728 | 기본 파생변수 확장의 개선 |
| 10차 | 2홉 이웃 블렌딩 | 약 0.730 | 커버리지는 늘지만 1홉 신호를 희석할 위험 |
| 11차 | 1홉 우선, 없을 때 2홉 폴백 | 약 0.730 | B 신호를 보존하며 C 일부를 보완 |
| 12차 | 도로망 위상 피처 정리 | 약 0.737 | 교차로와 주변 도로 구조가 유효 |
| 13차 | 인구·외부 맥락 추가 | 약 0.737 | 추가 개선은 제한적 |
| 14차 | 후보 피처 추가/정리 | 약 0.737 | 복잡도 증가 대비 이득이 작음 |
| 15차 | XGBoost로 알고리즘 변경 | 약 0.740 | 최종 부스팅 알고리즘 선택 |
| 16차 | 최종 61피처 구성 | 0.74029 | 노트북 내 최고 구성 |

16차 기록값은 R² 0.74029, MAE 4.32296 km/h, RMSE 6.2432 km/h입니다.

### 가장 중요한 이웃속도 해석

노트북의 이웃속도는 fold의 학습 링크가 **정확히 같은 날짜·시간에 관측한 속도**로 계산됩니다. 실험적으로는 인접 도로의 동시 혼잡 상태를 잘 포착해 강력하지만, 라이브 교통 피드가 없는 미래 시점에는 만들 수 없습니다.

그래서 공식 `src/models/02_build_model_bc.py`는 이 피처를 “관측 이웃의 시간코드×평일/주말 과거 평균”으로 바꿨습니다. 공식 검증 R² 약 0.7226이 실제 서빙 입력과 일치하는 값이며, 0.74029는 특징 선택과 모델 구조를 뒷받침하는 실험 상한으로 보고해야 합니다.

### 보고서에서의 올바른 문장

> 단계적 파생변수 실험에서 도로망 위상과 인접 링크 속도가 가장 큰 개선을 보였고, 최종 알고리즘으로 XGBoost를 선택하였다. 다만 동시점 이웃 관측은 미래 예측에 사용할 수 없어 운영 모델에서는 시간대·평일/주말 이력 버킷으로 대체하고 링크 단위 GroupKFold로 다시 검증하였다.

### 사용하면 안 되는 문장

> 최종 배포 모델의 R²는 0.740이다.

이는 노트북 피처와 실제 배포 피처 정의가 다르므로 부정확합니다.

## 3. `12b_model_a_history.ipynb`

### 목적

직접 관측 이력이 충분한 A 링크에서는 정적 B/C 모델보다 링크 자체의 반복적인 시간 패턴을 이용하는 것이 얼마나 유리한지 검증합니다.

### 관측 이력 상태

- 관측 링크: 44,960개
- 링크당 시간 관측 중앙값: 약 336개
- 링크의 약 99.8%가 가능한 기간의 80% 이상을 관측

14일 자료 안에서 대부분 A 링크가 거의 모든 시간에 관측되므로 링크별 시간대 이력을 만드는 조건은 좋습니다.

### 비교 결과

| 방식 | R² | 해석 |
| --- | ---: | --- |
| 링크 전체 평균 lookup | 약 0.7939 | 도로별 고유 평균만 사용 |
| 링크×시간 lookup | 약 0.9078 | 일중 패턴 추가 |
| 링크×시간×평일/주말 lookup | 약 0.9249 | 주중·주말 차이 추가 |
| 사전계획 LightGBM | 약 0.9276 | 알려진 사전 피처를 추가한 소폭 개선 |
| 실시간 정보 포함 시나리오 | 약 0.9454 | 라이브 정보가 있을 때의 상한 |

최종 lookup의 기록 MAE는 약 2.319 km/h, RMSE는 약 3.631 km/h입니다.

### 왜 공식 A는 단순 lookup인가

사전계획 LightGBM의 R² 개선은 약 0.0027로 작습니다. 반면 lookup은 해석이 쉽고, 빠르며, 외부 실시간 데이터 없이 모든 A 링크에 안정적으로 적용할 수 있습니다. 따라서 복잡도가 증가하는 모델보다 조회표를 공식 A로 선택했습니다.

### 주의

노트북의 split 조건과 현재 동일기간 전체 lookup을 비교하는 EDA는 서로 다릅니다. 독립 split에서의 0.9249와 현재 후향적 같은 기간 진단의 오차를 한 표에서 같은 평가로 섞지 않아야 합니다.

또한 노트북의 `src/13_predict_all_link_speed.py` 같은 경로는 옛 구조입니다. 현재 파일은 `src/models/03_predict_all_link_speed.py`입니다.

## 4. `13_tier_split_evaluation.ipynb`

### 목적

미관측 링크를 하나의 모델로 처리하지 않고, 관측 이웃이 있는 B와 없는 C를 분리해야 하는지를 직접 검증합니다. 임의 링크 분할뿐 아니라 공간 블록 분할을 사용해 가까운 도로의 정보가 train/test에 섞이는 문제도 진단합니다.

### 노트북 당시 계층 구성

1홉의 정확한 동시점 이웃 정의를 사용했기 때문에 현재 배포 계층 수와 다릅니다.

| 계층 | 링크 수 | 비율 |
| --- | ---: | ---: |
| A | 44,960 | 70.7% |
| B | 14,006 | 22.0% |
| C | 4,582 | 7.2% |

현재 배포는 2홉 폴백과 버킷 이웃 조회표를 사용해 B 16,752, C 1,836으로 바뀌었습니다.

### 핵심 발견

- B 링크에서는 이웃속도 피처가 R²를 약 +0.067 개선했습니다.
- C 링크에서는 이웃속도 열을 결측으로 둔 단일모델이 오히려 R²를 약 -0.178 악화시켰습니다.
- 따라서 B는 이웃속도 포함 모델, C는 정적 전용 모델로 분리하는 것이 타당합니다.

### 기록된 계층별 결과

| 계층 | R² | MAE |
| --- | ---: | ---: |
| A | 약 0.877 | 약 2.75 km/h |
| B | 약 0.780 | 약 5.49 km/h |
| C | 약 0.492 | 약 5.99 km/h |
| 계층 가중 전체 | - | 약 3.59 km/h |

이 수치는 계층 분리의 필요성을 보여 주는 실험 결과입니다. 현재 배포 버킷 정의로 다시 평가한 공식 B/C 점수와 동일하지 않습니다.

### 공간 평가의 의미

링크 단위 또는 2km 공간 블록 분할은 인접한 같은 도로 구간이 학습과 시험에 동시에 들어가는 것을 줄입니다. 실제 미관측 도로로의 공간 일반화를 평가하려면 행 단위 random split보다 이 결과를 우선해야 합니다.

## 5. 노트북 결과를 보고서에 배치하는 순서

1. 관측속도 EDA로 실제 현상을 먼저 제시합니다.
2. `11`로 비선형 부스팅 알고리즘 선택 배경을 짧게 설명합니다.
3. `12_derived`로 피처 개발과 이웃속도 효과를 설명합니다.
4. `13_tier`로 B/C 분리 설계를 정당화합니다.
5. `12_model_a`로 관측 이력이 있는 링크에 별도 A lookup을 쓰는 이유를 설명합니다.
6. 마지막에 공식 코드의 배포 정의와 검증 결과를 별도 표로 제시합니다.

이 순서를 쓰면 “관측 데이터에서 무엇을 보았는가 → 어떤 모델을 선택했는가 → 왜 계층화했는가 → 실제로 무엇을 배포했는가”가 자연스럽게 이어집니다.

| 결과 종류 | 평가/입력 조건 | 수치의 역할 |
