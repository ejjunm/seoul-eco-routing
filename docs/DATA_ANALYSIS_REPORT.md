# 서울 전기차 에코라우팅 데이터 분석 보고서 초안

발표용 원본은 [`데이터분석보고서.pdf`](../데이터분석보고서.pdf)(PPT 형식)이며, 이 문서는 같은 내용을 서술형으로 정리한 버전입니다.

## 초록

본 프로젝트는 서울 표준노드링크 63,548개와 5분 단위 교통속도, 도로 기하·위상, DEM 경사도, KMA 레이더 강수, 교통량·생활인구 자료를 결합해 시간별 전 링크 속도를 구축하고 Nissan Leaf 기준 전기차 에너지 비용을 추정한다. 분석기간은 2026년 7월 7일부터 20일까지 14일이며, 공통 레이더 입력이 없는 7월 7일 00시를 제외한 335개 시점을 사용하였다.

실제 속도가 관측된 링크는 44,960개로 전체의 70.75%였다. 관측 이력이 있는 링크에는 링크×시간×평일/주말 이력 조회 방식인 Model A를, 미관측 링크 중 관측 이웃의 역사적 시간대 속도를 만들 수 있는 16,752개에는 Model B XGBoost를, 이웃속도도 없는 1,836개에는 Model C XGBoost를 적용하였다. 그 결과 시점마다 63,548개 링크의 속도를 결측 없이 생성하였다. 이 속도와 링크 길이·경사를 VT-CPEM 기반 물리식에 입력해 총 21,288,580 링크-시간의 통행시간과 배터리 에너지를 계산하였다.

관측속도 EDA에서는 도로등급·제한속도·시간대·위상 복잡도와 속도의 구조적 차이를 확인하였다. 같은 링크·시간·평일/주말을 맞춘 강수 비교에서는 강수가 강해질수록 속도가 낮아지는 방향이 나타났으나 10mm 이상 구간의 평균 차이도 약 -0.59km/h로 크지 않았다. 관측속도를 에너지식에 넣은 결과 경사는 가장 강한 물리적 요인으로, -1~1% 구간 약 92.85Wh/km에서 6% 이상 오르막 약 626.76Wh/km까지 증가하였다. 다만 에너지 값은 실측 전력이 아니라 평균속도 일정, 회생제동 없음 등의 가정을 둔 추정치다.

전 링크 속도·에너지를 간선 가중치로 삼아 대표 30개 OD에 대해 Dijkstra 기반 경로 비교를 수행한 결과, 무제약 최소에너지 경로는 최단시간 대비 평균 12.389%의 에너지를 절감하지만 통행시간은 평균 20.256% 늘어났다. 최단시간 대비 15% 지연을 상한으로 둔 Pareto 균형경로는 평균 8.294%의 에너지를 절감하면서 시간 증가를 평균 8.152%로 억제하였다.

## 1. 연구 배경과 문제 정의

일반적인 경로안내는 거리 또는 통행시간을 최소화한다. 전기차에서는 같은 거리라도 속도, 통과시간, 경사에 따라 배터리 소모가 달라질 수 있으므로 최소시간 경로가 최소에너지 경로와 일치하지 않을 수 있다. 이를 비교하려면 모든 도로 링크에 같은 시점의 통행시간과 에너지 비용이 있어야 한다.

서울 표준노드링크는 63,548개지만 5분 속도 원자료에서 직접 관측되는 링크는 44,960개다. 관측 링크만 사용하면 도로망 일부의 비용이 비어 경로탐색이 제한된다. 따라서 본 연구의 핵심 문제는 다음 세 단계로 나뉜다.

1. 관측속도에서 실제 교통 현상과 데이터 품질을 파악한다.
2. 관측되지 않은 29.25%의 링크 속도를 공간·도로·시간·기상 피처로 추정해 전 링크 비용을 완성한다.
3. 링크 속도를 전기차 에너지로 변환하고 거리·시간·에너지 기준 경로를 비교할 수 있는 간선 비용을 만든다.

### 2.3 데이터 품질

5분 관측은 `LINK_ID×날짜×시간`으로 평균하고 실제 표본수를 `sample_count_5min`에 보존하였다. 한 시간의 최대 12개 관측이 모두 존재하지 않는 경우가 있으므로 학습 시 이 값을 표본 가중치로 사용하였다. DEM은 모든 링크에서 표본화됐지만 짧은 링크의 고도차를 길이로 나누면 비현실적인 경사가 발생할 수 있다. 따라서 에너지 계산은 ±12%로 제한하고 원경사와 이상치 플래그를 함께 저장하였다.

교통량과 View-T 피처는 약 60.7%가 결측이다. 이는 교통량 0을 뜻하지 않고 미조사 또는 매칭되지 않음을 뜻하므로 결측을 0으로 대체하지 않았다. 반대로 시설 카운트 0은 주변에 해당 시설이 없다는 의미가 명확해 0으로 채웠다.

## 3. 분석 방법

### 3.1 관측속도 우선 EDA

모델이 만든 속도를 먼저 분석하면 모델 구조가 만든 관계를 실제 현상으로 오인할 수 있다. 따라서 본 연구에서는 실제 `평균속도`가 있는 A-Observed 자료로 다음 관계를 먼저 분석했다.

- 시간대 및 평일/주말
- 도로등급과 제한속도
- 경사와 도로등급의 상호작용
- 같은 링크·시간대를 매칭한 강수 효과
- 교통량과 첨두시간
- 노드 복잡도
- 피처와 속도의 Spearman 순위상관
- 링크별 공간 평균속도

### 3.2 전 링크 속도 계층화

#### Model A

직접 관측 이력이 있는 링크는 과거 같은 시간대 패턴이 강하다. `LINK_ID×시간코드×평일/주말` 평균을 우선 사용하고 자료가 희소한 조합은 링크×시간, 링크 전체, 전역 평균 순으로 폴백한다. 단순하지만 사전 경로계획 시 사용할 수 없는 실시간 피처가 필요 없고, 14-fold Leave-One-Day-Out 교차검증에서 시간별 평균 MAE 2.54km/h·RMSE 4.19km/h를 기록해 공식 A 방식으로 선택했다. 같은 검증에서 요일별(7단계) 버킷은 셀당 표본 부족으로 과적합돼, 평일/주말 2단계 버킷이 더 우수함을 확인했다.

#### Model B

자체 관측은 없지만 표준노드링크 위상상 1홉 또는 2홉에 관측 링크가 있는 경우다. 관측 이웃들의 동일 시간코드·평일/주말 역사 평균을 `neighbor_speed_bucket`으로 만들고, 60개 공통 피처와 함께 XGBoost에 입력한다.

#### Model C

관측 이웃속도도 만들 수 없는 링크다. B 모델의 이웃속도 열을 결측으로 넣는 대신 해당 열을 완전히 제거한 별도 XGBoost를 사용한다. 계층분리 노트북에서 B에는 이웃속도가 도움이 됐으나 C에서는 결측 이웃 열을 공유한 단일모델이 성능을 크게 떨어뜨렸기 때문이다.

### 3.3 알고리즘 선택과 피처 중요도

**베이스라인 검토**(도로 속성 23개만 사용, 무작위 분할)에서는 규칙 기반 방법의 한계와 트리 모델의 우위를 함께 확인했다.

| 방법 | 설명 | R² |
| --- | --- | ---: |
| 전체 평균 | 모든 링크에 동일한 평균 속도로 예측 | 0.000 |
| 제한속도 선형회귀 | 도로 제한속도만으로 속도 추정 | 0.172 |
| 도로등급별 평균 | 도로 등급별 평균 속도 예측 | 0.266 |
| LightGBM | 원본 속성 23개(제한속도·차로수 등)를 반영한 트리 모델 | 0.610 |
| XGBoost | 위와 동일한 23개 속성 | 0.632 |
| CatBoost | 위와 동일한 23개 속성 | 0.556 |

**최종 비교**(파생 피처 포함 60개 정제 피처, 링크 단위 GroupKFold)에서는 LightGBM R² 0.737, XGBoost R² 0.740으로 XGBoost를 채택했다. 하이퍼파라미터는 두 알고리즘 모두 기본값으로 통일했다. 베이스라인 대비 최종 모델의 성능 격차(R² 0.632→0.740)는 알고리즘 선택보다 피처 엔지니어링의 기여가 훨씬 컸음을 보여준다.

최종 피처는 총 61개(B 계층 기준, C 계층은 이웃속도를 제외한 60개)다.

| 분류 | 개수 |
| --- | ---: |
| 도로 기본속성·지형·시간 | 22 |
| 도로망 위상·파생 | 18 |
| 코리도/도심거리 | 5 |
| 혼잡강도·평균속도(View-T) | 5 |
| 외부 컨텍스트(버스전용차로·스쿨존·과속방지턱·교통량) | 7 |
| 생활인구 | 2 |
| 이웃속도 | 1 |
| 교차로 유형 | 1 |

피처 중요도는 gain(트리 분기 시 손실 개선량) 대신 **SHAP**(Shapley value, TreeSHAP)으로 산출했다. gain은 상관된 피처 간 기여도가 왜곡될 수 있어(예: 초기 피처 구성에서 `REST_VEH`의 gain이 71%에 달했으나 구조 피처 추가 후 1.4%로 급락한 사례), 방향성까지 보여주는 SHAP을 기준으로 삼았다. B 계층 표본 20,000행 기준 상위 피처는 다음과 같다.

| 피처 | 비중 |
| --- | ---: |
| 이웃 도로 속도 | 35.6% |
| 시간대별 평균 속도(View-T) | 7.2% |
| 동일 도로명 구간 길이(코리도) | 4.6% |
| 시간대 | 3.3% |
| 진입차로수 평균 | 3.1% |
| 제한속도×차로수 | 3.0% |

이웃 도로 속도 하나가 전체 기여도의 1/3 이상을 차지했고, 값이 높을수록 예측 속도도 함께 상승하는 방향성을 보여 "주변이 막히면 이 도로도 막힌다"는 공간적 상관관계가 예측의 핵심 근거임을 확인했다.

### 3.4 검증 설계

속도 자료를 행 단위로 무작위 분할하면 같은 링크의 다른 시간이 train과 test에 동시에 들어가 링크 고유 특성을 사실상 외우게 된다. 공식 B/C 검증은 `LINK_ID`를 그룹으로 둔 3-fold GroupKFold를 사용하고, 각 fold의 이웃속도 조회표도 train 링크만으로 다시 만든다. 이때 현재 배포와 같은 역사 버킷 이웃 정의의 평균 R²는 약 0.7226이다.

노트북의 최종 16차 R² 0.74029는 같은 날짜·시간의 이웃 실측값을 이용한 결과다. 이는 피처의 잠재력과 알고리즘 선택 근거이지만 라이브 이웃 피드가 없는 현재 배포성능으로 사용하지 않았다.

### 3.5 에너지 계산

한 링크 안에서 평균속도가 일정하고 가속도가 0이라고 가정한다. 구름저항, 경사저항, 공기저항을 합해 바퀴 동력을 구하고 구동계·모터·배터리 효율과 700W 보조전력을 적용한다. 차량은 Nissan Leaf 기준 질량 1,521kg, 공기저항계수 0.28, 전면적 2.3316m²를 사용하였다.

내리막의 음의 바퀴동력은 회생발전으로 환산하지 않고 추진전력 0으로 제한한다. 따라서 현재 결과는 회생제동이 없는 보수적 단방향 소비 근사다. 경로탐색에는 길이 정규화값 `Wh/km`가 아니라 링크 총에너지 `energy_ev_j`를 사용해야 한다.

## 4. 결과

### 4.1 관측속도 범위와 시간 패턴

335개 시점에서 관측 A 링크의 길이/총통행시간 기반 네트워크 속도는 최소 약 14.71km/h, 평균 약 20.77km/h, 최대 약 24.93km/h였다. 링크-시간 산술평균은 약 17.27~28.15km/h로 더 높았다. 네트워크 속도는 느린 링크의 긴 통행시간을 더 크게 반영하므로 산술평균과 다르다.

평일과 주말의 시간 프로필이 다르고 평일 첨두시간대에 속도가 낮아지는 구조가 나타났다. 이는 시간코드뿐 아니라 주말 여부와 시간의 sin/cos 순환 인코딩을 사용한 근거다.

### 4.2 도로 속성과 실제 속도

도로등급별 실제 평균속도는 다음과 같이 구조적인 차이를 보였다.

| ROAD_RANK | 평균속도(km/h) |
| --- | ---: |
| 101 | 63.22 |
| 102 | 49.93 |
| 103 | 27.40 |
| 104 | 21.03 |
| 105 | 37.85 |
| 106 | 28.55 |
| 107 | 25.27 |

제한속도 구간도 ≤30km/h 도로 약 18.68km/h에서 80km/h 초과 도로 약 80.22km/h까지 단조 증가했다. 이는 `ROAD_RANK`와 `MAX_SPD`가 링크의 기본 속도 수준을 구분하는 핵심 피처임을 보여 준다.

노드 복잡도 ≤2 구간은 약 33.22km/h였고 6~10 구간은 약 20.74km/h였다. 복잡한 교차로 주변일수록 저속인 방향이지만 극단 구간의 표본이 작고 도로등급 구성이 다르므로 독립적인 인과효과로 보기는 어렵다.

### 4.3 강수와 실제 속도

강수일과 비강수일의 도로·시간 구성 차이를 줄이기 위해 같은 `LINK_ID×시간×평일/주말` 조합의 마른 날 평균을 기준으로 매칭했다.

| 강수 구간(mm) | 젖은 날−마른 날 속도(km/h) |
| --- | ---: |
| 0~1 | -0.059 |
| 1~5 | -0.073 |
| 5~10 | -0.172 |
| 10+ | -0.592 |

강수가 강할수록 속도가 감소하는 방향은 일관되지만 절대 크기는 작다. 특히 14일의 짧은 기간과 강수일의 고유한 사고·혼잡을 분리하지 못했으므로 “강수의 인과효과”가 아니라 조건부 연관성으로 보고한다.

### 4.4 관측속도 기반 에너지

관측 A 링크의 시간별 네트워크 에너지 원단위는 최소 약 128.95Wh/km, 평균 약 132.54Wh/km, 최대 약 140.45Wh/km였다. 경사별 결과는 다음과 같다.

| 방향성 경사 | 평균 에너지(Wh/km) |
| --- | ---: |
| ≤-6% | 38.25 |
| -6~-3% | 39.30 |
| -3~-1% | 39.97 |
| -1~1% | 92.85 |
| 1~3% | 192.24 |
| 3~6% | 326.40 |
| ≥6% | 626.76 |

오르막에서 중력저항이 급격히 증가해 에너지 원단위가 커졌다. 내리막은 바퀴동력이 음수이면 추진전력을 0으로 만들고 보조전력만 소비하기 때문에 낮은 값이 나타난다. 이 결과를 실제 회생량으로 해석해서는 안 된다.

도로등급별 에너지 원단위는 101 약 158.49, 102 129.47, 103 121.10, 104 134.36, 105 112.66, 106 130.66, 107 137.24Wh/km였다. 고속 등급이 항상 가장 효율적이지 않은 것은 고속에서 공기저항이 속도의 제곱으로 증가하고 도로별 경사 구성이 다르기 때문이다.

### 4.5 A lookup의 실제값 재현 정도

같은 시점·링크의 A actual과 A lookup을 비교했을 때 시간별 MAE 평균은 약 2.54km/h, 시간별 RMSE 평균은 약 4.19km/h, 평균 편향은 약 -0.47km/h였다. 에너지 원단위 MAE는 약 4.72Wh/km였다.

조회표는 반복적인 시간패턴을 잘 포착하지만 특정 날짜의 비반복적 혼잡을 평균으로 되돌리는 특성이 있다. 음의 편향은 전체적으로 lookup이 actual보다 약간 낮았음을 뜻한다. 그러나 조회표 구축에 비교기간 전체가 들어갔기 때문에 이는 외부시험이 아니라 후향적 적합도 진단이다.

### 4.6 전 링크 속도와 에너지

시점마다 A 44,960, B 16,752, C 1,836개 링크를 결합해 총 63,548개 링크를 완성하였다. 모든 335개 파일에서 속도 결측은 없었다. 첫 시점의 속도 범위는 3.0~102.651km/h, 평균은 약 24.15km/h였으며 최종 예측은 최소 3km/h와 링크 제한속도 사이로 제한됐다.

전 링크의 네트워크 속도는 335시간 동안 최소 약 16.50, 평균 약 19.78, 최대 약 22.94km/h였다. 네트워크 에너지 원단위는 최소 약 133.34, 평균 약 135.86, 최대 약 139.71Wh/km였다. 관측 A만의 값과 차이가 나는 이유는 B/C가 주로 일반도로·이면도로 등 다른 도로 구성에 속하기 때문이다. 이 차이를 곧바로 B/C 예측오차로 해석할 수 없다.

에너지 Parquet은 모든 시점에서 링크당 총에너지, 통행시간, 힘·동력 중간항을 가지고 있으며 결측 또는 음의 에너지는 0건이다. 매 시점 원경사 3,430개가 ±12% 밖으로 판정돼 계산경사가 보정되었다.

## 5. 라우팅(Stage 3)

라우팅은 방향성 그래프(`F_NODE→T_NODE`)에서 동일 OD에 대해 링크 가중치를 바꾸는 Dijkstra 최적화다.

시간 비용은 링크 길이를 예측 속도(km/h를 m/s로 환산)로 나눈 통행시간이고, 에너지 비용은 3.5절의 물리식으로 구한 배터리 전력을 통행시간 동안 적분한 값이다. 최단시간 경로는 각 후보 경로의 링크별 시간 비용 합이 최소인 경로이고, 에코(최소에너지) 경로는 같은 방식으로 링크별 에너지 비용 합이 최소인 경로다.

무제약 최소에너지 경로는 시간 증가를 고려하지 않으므로, 실사용을 고려해 **Pareto Label-Setting 알고리즘**으로 "최단시간 대비 허용 시간 증가율" 제약 안에서 에너지를 최소화하는 **균형 경로**를 추가로 탐색한다.

2026-07-16 08:00 스냅샷, 대표 30개 OD 기준 결과는 다음과 같다.

| 경로 | 평균 에너지 절감 | 평균 시간 증가 |
| --- | ---: | ---: |
| 무제약 최소에너지 | 12.389% | 20.256% |
| 15% 지연 상한 균형경로 | 8.294% | 8.152% |

무제약 최소에너지 경로는 의미 있는 절감을 제공하지만 시간 증가도 크다. 반면 최단시간 대비 최대 15% 지연만 허용한 균형경로는 평균 약 8.3%의 에너지를 절감하면서 실제 시간 증가는 평균 약 8.2%로 억제된다. 다만 이 15% 상한은 분석상 설정값이며, 실제 이용자의 수용 가능성은 별도 선호조사가 필요하다.

라우팅 결과는 지도 GeoJSON, 선택 경로 강조, 도로명 기준 구간 안내, 거리·시간·에너지 합계와 함께 대시보드(Leaflet + FastAPI)로 제공되며, 동일 경사 대비 에너지 소모가 비정상적으로 큰 구간을 스크리닝해 에너지 비효율 도로 구간을 진단하는 데도 쓰인다.

## 6. 논의

### 6.1 왜 관측 EDA가 예측 EDA보다 먼저인가

예측 데이터의 관계는 모델 피처와 제약에서 만들어질 수 있다. 예를 들어 B/C 모델에 강수를 넣었기 때문에 예측속도와 강수의 관계가 나타나는 것은 실제 현상과 모델 반응이 섞인 결과다. 반면 A-Observed에서 먼저 확인한 관계는 최소한 모델 출력으로 생성된 패턴은 아니다. 그러므로 보고서의 실증 근거는 관측 EDA에 두고, 예측 EDA는 전 링크 확장 후 물리적 일관성·분포·공간 커버리지를 점검하는 용도로 둔다.

### 6.2 A가 정답인가

“A 링크”와 “A 속도값”을 분리해야 한다. A는 그 링크가 관측 이력을 가진다는 계층명이다. 해당 날짜·시간의 `평균속도`는 실제 관측값이지만 `model_a_lookup.parquet`의 `pred_speed`는 여러 날짜의 같은 시간대 평균이므로 예측값이다. 과거 하이브리드 자료는 실제 A가 있는 순간만 actual로 교체하고 나머지를 lookup 또는 B/C로 유지한다.

### 6.3 속도와 에너지의 비선형성

저속에서는 링크를 오래 통과해 700W 보조전력 소비가 거리당 커지고, 고속에서는 공기저항이 증가한다. 여기에 방향성 경사저항이 더해져 같은 속도라도 에너지가 크게 달라진다. 따라서 최소시간 경로와 최소에너지 경로가 반드시 같지 않으며, 단순히 속도가 낮은 도로 또는 짧은 도로가 에너지 최소라고 할 수 없다.

## 7. 한계

1. 14일 자료는 장기 계절성, 겨울철 난방부하, 휴일·행사 효과를 대표하지 못한다.
2. A lookup 동일기간 진단에는 전체기간 정보가 들어가 독립 시험이 아니다.
3. B/C의 실제 미관측 링크에는 정답이 없고 관측 링크를 가상 미관측으로 만든 공간검증에 의존한다. 실제 미관측 링크와 이 가상 미관측 A 링크의 분포가 다를 수 있어 대리검증 R²가 실제 성능을 정확히 대표하지 않을 수 있다.
4. 교통량과 View-T는 희소하고(약 60.7% 결측) 2024년 평일 기준 자료라 2026년 7월 관측과 시점·요일 구성이 다르며, 실시간 값 대신 같은 시간대 과거 프로필을 사용한다.
5. KMA 격자를 링크 중심점 최근접으로 붙여 국지 강수의 공간 오차가 있다.
6. DEM 해상도와 짧은 링크 때문에 경사 오차가 있으며 ±12% clipping은 편의적 안정화다.
7. 에너지식은 링크 내 정속, 가속도 0, 회생제동 없음, 고정 보조전력, 단일 차량을 가정한다.
8. 신호대기, 정지·출발, 급가감속, 노면상태, 온도, HVAC, 배터리 SOC를 반영하지 않는다.
9. 실제 차량 전력 또는 주행시험으로 에너지 결과를 보정하지 않았다.
10. 라우팅은 선택한 시각의 정적 스냅샷 기준이며, 신호대기·교차로 회전비용·공사·통제·실시간 교통 변화는 반영하지 않는다. 실서비스 내비게이션이 아니라 연구용 경로 비교 프로토타입이다.

## 8. 결론

본 연구는 관측 가능한 서울 링크의 실제 시간속도를 기반으로 관측되지 않은 링크를 계층형 A/B/C 방식으로 보완해 335시간×63,548링크의 속도와 에너지 비용을 완성하였다. 관측 EDA에서 제한속도·도로등급·시간대·위상 구조와 속도의 뚜렷한 연관을 확인했고, 매칭 강수 분석에서는 강수 강도가 클수록 속도가 낮아지는 약한 방향성을 확인했다. Nissan Leaf 기반 물리모델에서는 방향성 경사가 에너지 원단위의 핵심 요인이었다.

성과는 단순히 “전 링크 값이 존재한다”는 데 그치지 않는다. 관측값, A 이력 예측, B/C 예측, 물리모델 에너지를 구분하고 각 단계의 출처와 신뢰수준을 보존해 결과를 감사할 수 있게 만들었다. 이를 바탕으로 Dijkstra 및 Pareto Label-Setting 알고리즘으로 최단시간·최소에너지·균형 경로를 실제로 비교했고(5장), 15% 지연 상한 균형경로가 시간 부담을 크게 늘리지 않으면서 의미 있는 에너지 절감을 제공함을 확인했다. 향후 장기 자료, 라이브 교통, 실차 전력 검증, 회생제동·가감속 모델을 추가하면 더 현실적인 전기차 경로추천으로 확장할 수 있다.

## 10. 후속 분석 우선순위

### 우선순위 1: 평가의 독립성 강화

- A lookup을 train 기간만으로 만들고 마지막 날짜들을 test로 두는 rolling-origin 평가
- B/C도 시간 holdout과 공간 GroupKFold를 동시에 적용
- 계층별 MAE/RMSE/R² 외에 속도구간·도로등급·강수별 오차 보고

### 우선순위 2: 에너지 현실성 검증

- 실차 또는 공개 EV 주행데이터로 Wh/km 보정
- 정지·출발 및 링크 진입/진출 속도를 이용한 가속도 항
- 회생제동 효율과 배터리 충전 한계
- 기온·냉난방·SOC별 보조전력 시나리오
- 경사 clipping 민감도(±8, ±10, ±12, ±15%)

### 우선순위 3: 라우팅 안정화

`src/routing/engine.py`(Dijkstra)와 `01_route_compare.py`/`02_evaluate_route_scenarios.py`로 최단시간·최소에너지·균형(Pareto) 경로 비교가 재현 가능한 상태다. 다만 다음은 아직 보강이 필요하다.

- OD·스냅 노드·시점·차량 파라미터를 config로 고정해 실행 재현성 강화
- 연결 불가 OD와 최대 강연결요소 필터 결과 기록
- 거리·시간·에너지 trade-off를 30개 OD 외 더 많은 지점·시간대로 확장해 bootstrap 요약
- 15% 외 다른 지연 상한(10%, 20% 등)에서의 민감도 비교

### 우선순위 4: 장기 일반화

- 최소 수개월의 계절·요일·공휴일 자료 확보
- 사건·공사·신호·제한속도 변경 자료 결합
- B/C 직접 검증을 위한 표본 미관측 링크 현장 또는 외부 속도 소스 확보
